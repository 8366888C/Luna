## Why Clean Code Matters

Clean code is not just about aesthetics—it's about communication. Code is read far more often than it's written.

### The Boy Scout Rule

> Always leave the code better than you found it.

## Core Principles

### 1. Meaningful Names

```typescript
// Bad
function d(users) {
  return users.filter(u => u.a > 18);
}

// Good
function getAdultUsers(users) {
  return users.filter(user => user.age > ADULT_AGE);
}
```

### 2. Small Functions

Each function should do one thing well:

```typescript
// Do one thing
function validateEmail(email) {
  return email.includes("@");
}

function formatEmail(email) {
  return email.trim().toLowerCase();
}
```

### 3. Avoid Magic Numbers

```typescript
// Bad
if (days > 30) { ... }

// Good
const THIRTY_DAYS = 30;
if (days > THIRTY_DAYS) { ... }
```

### 4. Comments Explain Why, Not What

```typescript
// Bad
// Increment counter
counter++;

// Good
// Compensate for off-by-one in array indexing
counter++;
```

## The Refactoring Process

1. **Identify** - Find complex or duplicated code
2. **Test** - Ensure tests pass
3. **Refactor** - Make changes
4. **Verify** - Tests still pass

## Code Review Checklist

- [ ] Names are descriptive
- [ ] Functions are small
- [ ] No duplicated logic
- [ ] Error handling exists
- [ ] Tests cover the code

## Conclusion

Writing clean code is a discipline. It requires constant attention and refactoring. The payoff is code that's easier to understand, debug, and extend.
