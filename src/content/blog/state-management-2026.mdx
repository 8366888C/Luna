## The State Management Landscape

State management has evolved significantly. Here's what's relevant in 2026.

## Server State vs Client State

### Server State
- Data from the server
- Needs caching, revalidation
- Tools: TanStack Query, SWR

### Client State
- UI state, theme, user input
- Local only
- Tools: Zustand, Jotai, Signals

## TanStack Query (Server State)

```typescript
import { useQuery, useMutation } from "@tanstack/react-query";

function UserList() {
  const { data, isLoading } = useQuery({
    queryKey: ["users"],

  if (isLoading) return <Loading />;

```

## Zustand (Client State)

```typescript
import { create } from "zustand";

const useStore = create((set) => ({
  theme: "dark",
  toggleTheme: () => set((s) => ({ 
    theme: s.theme === "dark" ? "light" : "dark" 
  })),
}));

function ThemeToggle() {
  const { theme, toggleTheme } = useStore();
  return <button onClick={toggleTheme}>{theme}</button>;
}
```

## Jotai (Atomic State)

```typescript
import { atom, useAtom } from "jotai";

const countAtom = atom(0);
const doubledAtom = atom((get) => get(countAtom) * 2);

function Counter() {
  const [count, setCount] = useAtom(countAtom);
  const [doubled] = useAtom(doubledAtom);
  
  return (
    <div>
      Count: {count} (doubled: {doubled})
      <button onClick={() => setCount(c => c + 1)}>+1</button>
    </div>
  );
}
```

## Signals (The New Approach)

```typescript
import { signal, computed } from "@preact/signals";

const count = signal(0);
const doubled = computed(() => count.value * 2);

// In components
const value = count.value;
count.value = 5;
```

## Choosing

| Need | Tool |
|------|------|
| Server caching | TanStack Query |
| Simple global UI | Zustand |
| Atomic/derived | Jotai |
| Fine-grained | Signals |
| Complex server + client | Redux Toolkit |
