## Git Flow

A structured workflow with feature branches, develop, and main branches.

### Branches

- `main` - Production code
- `develop` - Integration branch
- `feature/*` - New features
- `hotfix/*` - Emergency fixes

### Pros
- Clear separation of concerns
- Good for scheduled releases

### Cons
- Complex for small teams
- Multiple long-lived branches

## GitHub Flow

Simpler workflow with feature branches and PRs.

### Rules

1. Branch from main
2. Make small, frequent PRs
3. Ship to main after review
4. Deploy immediately

### Best For
- Continuous deployment
- Small teams
- Web applications

## Trunk-Based Development

Developers work on main with short-lived feature branches.

### Key Practices

- Small commits
- Frequent integration
- Feature flags for incomplete features

### Benefits
- Fast feedback
- Reduced merge conflicts
- Continuous integration

## Choosing a Workflow

| Team Size | Recommended |
|----------|-------------|
| 1-3 | GitHub Flow |
| 5-20 | Trunk-Based |
| 20+ | Git Flow |

## Best Practices

1. Write good commit messages
2. Squash commits before merging
3. Use CI/CD pipelines
4. Review code in pairs
